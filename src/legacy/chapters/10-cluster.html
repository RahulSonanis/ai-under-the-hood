How do thousands of chips train one model?

Short answer

The work is split several ways at once: different chips read different data, big matrix maths is cut into pieces, and the layers are spread along an assembly line. After every step, all the chips combine what they learned over very fast networks.

Ring all-reduce: how GPUs agree on one update

Real algorithm · step by step

Each GPU computed its own gradients from its own slice of data (four numbers each, below). They must all end up with the sum. Press Next step: each GPU passes one chunk to its neighbour around the ring. After 2×(GPUs−1) steps everyone has the same totals.

Ring all-reduce has each GPU send and receive about 2·(n−1)/n of the data in total, so the bandwidth each GPU needs barely changes with how many take part, which is why it scales. Latency does grow with the number of steps, which is one reason libraries also use trees. NCCL chooses between rings, trees and other patterns depending on the network2.

Why one chip isn't enough

The model is too big to fit in one chip's memory, and training it on one chip would take centuries. So thousands of chips each take a piece of the job.

Training needs to store not just the model but extra copies for learning: the slopes, and the optimiser's running averages. That's about 16 bytes per parameter, so a 70-billion-parameter model needs over a terabyte before counting anything else. An H100 has 80 GB.

Mixed-precision Adam keeps BF16 weights and gradients (2+2 bytes) plus FP32 master weights and two moments (12 bytes)11, plus activations that grow with sequence length. Teams combine several kinds of parallelism: data parallel (different batches, average gradients; ZeRO/FSDP also shard the 16 bytes), tensor parallel (split each matrix multiply, needs the fastest links, so kept inside one NVLink domain12), pipeline parallel (split layers), expert parallel (spread MoE experts) and context parallel (split long sequences)2.

Per-GPU model-state memory ≈ 16Ψ / (t·p) bytes before sharding, divided further by the DP degree d for whichever of optimiser state, gradients and weights ZeRO stage 1/2/3 shards. Activation memory per layer ≈ s·b·h·(34 + 5·a·s/h) bytes without recomputation52. Total GPUs = d·t·p (×e for expert parallel, which typically reuses the data-parallel ranks).

Symbols: Ψ parameters · d data-parallel degree · t tensor-parallel degree · p pipeline stages · s sequence length · b micro-batch size · h hidden size · a attention heads · e expert-parallel degree

Two networks: scale-up and scale-out

Chips in the same box talk over a super-fast private road. Boxes talk to each other over a big motorway. Jobs are arranged so the chattiest work stays on the private road.

Every training step ends with chips swapping results, and the whole job waits for the slowest link. So clusters have a very fast network inside each server or rack and a fast but slower one connecting thousands of them.

Scale-up: NVLink inside an 8-GPU server or a 72-GPU NVL72 rack (130 TB/s total)22, NeuronLink on Trainium, ICI on TPU pods. Scale-out: InfiniBand or RDMA over Ethernet (RoCE), or AWS's Elastic Fabric Adapter, in non-blocking fat-tree topologies. Meta built two 24,576-GPU clusters, one on each fabric, and tuned both to train without network bottlenecks; Llama 3 405B trained on the Ethernet (RoCE) cluster and the smaller Llama 3 models on InfiniBand149.

Check yourself

Why is tensor parallelism usually kept within a single server or rack?

Splitting each matrix multiply means partial results are combined many times per step; only NVLink-class bandwidth keeps up.

With 4 pipeline stages, how do you shrink the bubble?

Bubble fraction is (p−1)/(m+p−1), so more micro-batches m dilute the start-up and drain time.
