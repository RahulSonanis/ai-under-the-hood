How does text become numbers?

Chatbots that could write a sonnet in seconds used to insist that “strawberry” has two r's201. Part of the reason comes before the model does any thinking: it never sees the letters. In this chapter you build the machine that hides them.

What's going on

A model can only do arithmetic, so text has to become numbers first. A tokenizer cuts text into tokens, pieces taken from a fixed list called the vocabulary, and swaps each piece for its ID number. It starts from bytes: computers store every character as one to four small numbers between 0 and 255, so 256 starting tokens can spell any text in any language, emoji included.

The rest of the vocabulary is learned by byte-pair encoding: count every pair of neighbouring tokens in a large training text, glue the most common pair into a new token, and repeat. Your tokenizer has learned 0 merges from everyday English; the latest glued – into –. It cuts your 0 characters into 0 tokens, – per word. Real tokenizers learn from billions of words and keep tens of thousands of merges, so most common English words become a single token. On average an English token is about three-quarters of a word202.

Then each ID picks one row of the embedding table: a list of numbers the model learned for that token during training. From here on the model works only with those numbers. That's the catch with “strawberry”: the model receives one or a few IDs, not ten letters, so it can only count the r's if it has learned how each piece is spelled.

How it works bytes, merges, vocabulary size, embeddings

Bytes first. Text is stored as UTF-8: English letters take one byte each, accented letters two, Hindi letters three, most emoji four. GPT-2, OpenAI's 2019 model, ran byte-pair encoding on bytes instead of characters, so its tokenizer could encode any input without an “unknown” token. Its vocabulary stopped at 50,257 tokens63. The dashed boxes in the simulation are bytes that are only part of a character.

Words first, then merges. Before merging, text is split into rough words with a fixed pattern, so a merge never glues the end of one word to the start of the next. The space goes with the word after it, which is why you see “·the”. The simulation uses GPT-2's pattern63. Byte-pair encoding itself began as a 1994 file-compression trick, and was adapted for language in 2015 to split rare words into common pieces4.

How big a vocabulary? More merges make text shorter, so more fits in the model's working memory and each reply needs fewer steps. But every token adds a row to the embedding table and a choice to every prediction, and late merges glue rare pairs that save little, as you can see in the simulation. Meta's Llama 3 models use about 128,000 tokens9.

Languages cost differently. A tokenizer learns most merges for the languages that fill its training text. Text in rarer languages is split into more, smaller tokens, and how many tokens a word needs on average varies widely between languages64. Prices, speed limits and the model's maximum input are all counted in tokens, so the same message can cost more in one language than another.

Spelling is hidden. Because the model sees token IDs, anything about letters (spelling, rhymes, counting characters) has to be learned indirectly. A 2024 study found models can usually tell which letters a word contains but often miscount them, especially letters that appear more than twice201.

Embeddings. Looking a token up is just reading one row of the table. The rows start random and are adjusted during training (chapter 13) until tokens used in similar ways end up with similar rows. With older word-level models, researchers found that even directions in this space carried meaning, like a consistent step from “man” to “woman”56.

The maths one merge, step by step
In words

Count every pair of neighbouring tokens in the training text. Glue the most common pair into one new token. Everywhere that pair appeared, two tokens become one, so the training text gets shorter by that many tokens. Add the new token to the vocabulary and repeat.

With your numbers

Training text (everyday English): 0 bytes, so 0 tokens to start
Latest merge: – → –, which removed 0 tokens
After 0 merges: 0 − 0 = 0 tokens
Vocabulary: 256 + 0 = 256 tokens

In symbols
(a, b) = argmax count(x, y)
Nm = Nm−1 − cm
|V| = 256 + m

x, y any two tokens that sit next to each other · count(x, y) how often they do, across the whole training text · argmax “the pair that makes this largest” · (a, b) the winning pair, which becomes the new token “ab” · m the number of merges learned so far · Nm tokens in the training text after m merges (N0 is its number of bytes) · cm how many places merge m glued · |V| the size of the vocabulary. Each merge is chosen greedily: the best pair now, with no look-ahead.

Check yourself

Why can a model that writes fluent poems still miscount the letters in a word?

The tokenizer hands the model ID numbers for chunks. The letters inside a chunk are not part of what the model receives.

A byte-pair tokenizer learns one more merge. Which pair does it glue together?

Each merge picks the most frequent neighbouring pair, so common words get built first and rare ones stay in pieces.
